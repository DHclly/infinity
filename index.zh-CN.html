∞ .js

∞ 是一个 Web 版的 UITableView： 它加速长列表的滚动，让你的无限信息流保持流畅稳定。它小巧、 久经实战考验、性能出色。代码托管在 Github 上，并以 BSD 许可证发布。附带了 带注释的源码，以及分别关闭 Infinity 和开启 Infinity 的演示。

∞ 由 Airbnb 在开发热门心愿单和好友信息流的过程中打造，如今每天都在生产环境 投入使用。它唯一的依赖是 jQuery。

上手非常简单：

var $el = $('#my-infinite-container');
var listView = new infinity.ListView($el);

// ... 添加新内容时：

var $newContent = $('<p>Hello World</p>');
listView.append($newContent);

// ... 从列表中移除项时：

var listItems = listView.find('.my-items');
for(var index = 0, length = listItems.length; index < length; index++) {
  listItems[index].remove();
}

如需完整的 API 文档，请继续往下阅读。

ListView API 参考

一个 ListView 是一个容器， 在滚动事件触发时把内容移入和移出 DOM。 ListView 通过确保屏幕上永远不会同时出现太多元素， 来帮助降低高开销页面的重绘时间（并保持滚动流畅）。 ListView 擅长加速包含复杂 HTML 元素的长列表， 这类列表的新内容经常被追加到末尾， 而现有内容很少被移除。

ListView 很简单，但有几个注意事项：它们不能相互嵌套， 也不能通过 CSS 设置高度。此外，除了通过追加或移除元素， ListView 很难改变尺寸，因此需要展开或改变尺寸的列表项 会较难实现。向 ListView 追加元素相对较快， 但移除元素较慢 — 所以在高帧率下每秒需要多次移除元素的 设计会面临压力。

注意 由于 Firefox 对没有 src 属性的 <img> 标签 的实现方式与其他浏览器不同， 如果你在 ListView 内懒加载图片， 应把它们的 display 设置为 block 或 inline-block， 否则 Firefox 会向 Infinity 报告错误的高度数据。

属性

  • $el: 用作 ListView 父级的 jQuery 元素。
  • width: ListView 的宽度。
  • height: ListView 的高度。

方法

  • new ListView($el [, options]): 创建一个新的 ListView，把内容追加到给定的 jQuery 元素内部。传入的元素必须 已经在 DOM 中：否则，ListView 会缓存错误的 尺寸和定位数据。options 是一个选项 hash，可以填写 以下选项：
    • lazy: 一个用于懒加载屏幕上尚未加载的 ListItem 的函数，会以 ListItem 的 jQuery 元素作为其 上下文来调用。
  • append($el | listItem): 把一个 jQuery 元素 或一个 ListItem 追加到 ListView。返回给定的 ListItem， 或把给定的 jQuery 元素包装进一个新 ListItem 后返回。
  • find(selector | $el): 给定一个选择器或一个 jQuery 元素，返回包含该元素或匹配该选择器的 ListItem。 重要的是用 ListView 而不是 DOM 来查找你想要的项， 因为为了节省滚动性能，这些项经常会从 DOM 中被移除。 注意 find() 返回的是一个 ListItem 数组， 它们是对 jQuery 元素的包装，会缓存定位数据， 并能方便地与父 ListView 通信（这一步在 ListItem#remove() 操作中已经在后台处理好了）。
  • remove(): 把 ListView 从 DOM 中移除， 并清理相关资源。
  • cleanup(): 解绑所有事件，但不把 ListView 从 DOM 中移除。

ListItem API 参考

ListItem 是放置在 ListView 内部的各个 DOM 节点的包装。通常你不需要自己创建 ListItem： ListView 会自动为你传入的任何 jQuery 元素完成包装。 不过，你可能会发现单独与它们交互很有用 — 例如，如果你需要移除某个元素，应该通过调用该 ListItem 的 remove 来完成，这样它才能把移除操作告知父 ListView — 因此 ListView 让查看自己的 ListItem 集合变得很容易。

属性

  • $el: 该 ListItem 包装的 jQuery 元素。
  • top: ListItem 在屏幕上的顶部位置， 相对于其父 ListView。
  • bottom: ListItem 在屏幕上的底部位置， 相对于其父 ListView。
  • width: ListItem 的宽度。
  • height: ListItem 的高度。

方法

  • remove(): 把该 ListItem 从 ListView 中 永久移除，并把它对应的元素从 DOM 中移除， 最后清理一切相关资源。
  • cleanup(): 解绑所有事件并释放它持有的 所有引用，但不把该 ListItem 从 ListView 中移除。

配置 Infinity.js

我们尽量为 Infinity 选择了合理的默认值， 但有时会遇到我们没有考虑到的一些特殊场景。 Infinity.js 可以通过两个选项来配置， 以便在多种情况下都保证滚动流畅。配置选项如下：

  • infinity.config.PAGE_TO_SCREEN_RATIO: 在内部，Infinity.js 把它的 ListItem 放进一个个 Page（页）块中， 这个变量控制一页相对于视口大小应该有多大。 默认值为 3。页越大，意味着 Infinity 需要换页的频率越低；页越小，意味着渲染速度越快。 如果你的页非常复杂，可以调小这个值， 让屏幕上需要处理的内容更少以避免拖慢页面； 另一方面，如果你的页非常简单，可以调大这个值， 进一步降低换页突兀或滚动闪烁的可能性。
  • infinity.config.SCROLL_THROTTLE: Infinity.js 会对它的滚动事件进行节流：每 350 毫秒才响应一次滚动事件。 如果你希望它响应得更频繁或更不频繁，就把这个值设置成 你想要的节流毫秒数。如果你调大了 PAGE_TO_SCREEN_RATIO，可以调大 SCROLL_THROTTLE 以减少计算频率； 如果你调小了 PAGE_TO_SCREEN_RATIO， 大概也需要调小 SCROLL_THROTTLE， 以确保较小的页能更及时地被换到屏幕上， 因为此时你屏幕周围的缓冲更小。

未来工作

  • 把 Infinity 内部的数据结构从有序数组换成 自平衡二叉树。这会让 ListItem 上的 remove() 操作快得多， 并能简单、快速地支持前插（甚至任意位置插入）。
  • 做一个 API，在元素尺寸变化时通知 ListView/ListItem，让 ListView 能重新组织自身。 这可能是切换到自平衡二叉树之后的下一步。
  • 让缓冲区感知滚动方向，这样你可以根据滚动方向 只保留后置缓冲或只保留前置缓冲。这样就能在不影响 绘制时间的前提下，把 PAGE_TO_SCREEN_RATIO 稍微调大一些。
